# 구현 상태와 실제 장비 연동 전 점검

현재 프로젝트는 백엔드와 MQTT 관제 흐름을 검증할 수 있는 프로토타입이다. 실제 예초 장비를 안전하게 운용할 단계는 아니다.

## 실제 구현

- JWT 로그인과 역할 기반 접근 제어
- 로봇 REST API
- PostgreSQL/PostGIS 작업 구역 저장
- MQTT 명령 발행과 텔레메트리 수신·저장
- 제어권 획득, 충돌, 강제 인수
- 백엔드와 Jetson 데드맨 스위치
- Jetson MQTT 명령 검증과 ROS 2 변환
- MQTT ACK 상태 저장
- 이력·로그 백엔드 API

## Mock 또는 부분 구현

- 프론트엔드 실시간 telemetry store 연결
- 지도 경로와 작업 구역 편집
- 이력·로그 화면 데이터
- WebRTC 영상과 스냅샷
- RealSense D455 ROS 2 실행 환경과 카메라 노드
- Edge Mock의 장비 동작
- 배터리, 속도, 신호 세기 센서값

## 미구현

- 저장소에서 재현 가능한 STM32 firmware와 HIL 시험 자료
- STM32 완료 ACK를 백엔드 명령 lifecycle까지 전달하는 경로
- 작업 구역 이탈 감지와 자동 정지
- 실제 WebRTC/NVENC 영상
- 자율주행, Coverage Path Planning, 장애물 인식
- 운영용 HTTPS/WSS/MQTTS와 비밀정보 관리
- 실제 장비를 포함한 전체 E2E 시험

HW 팀은 Jetson-STM32 USB CDC 통신, PWM 출력과 watchdog을 HIL 환경에서 검증했다고 공유했다. 다만 해당 firmware와 시험 결과는 현재 저장소에서 독립적으로 재현할 수 없으므로 소프트웨어 팀의 완료 항목과 구분한다.

RealSense D455와 ROS 2 카메라 노드는 2026년 6월 12일 재확인에서 연결됐다. 원본 컬러 영상은 1280x720 약 28fps로 실제 프레임을 발행하지만 요청한 640x480 15fps 프로파일은 적용되지 않았다. 압축 컬러 토픽은 약 30Hz로 발행되지만 JPEG payload가 비어 있다. 카메라 원본 영상 발행과 웹 영상 송출 완료를 같은 상태로 취급하지 않는다.

## 실제 장비 연결 전 필수 조건

1. STM32가 통신 단절 시 독립적으로 PWM 중립과 블레이드 차단을 수행해야 한다.
2. E-Stop 활성화와 해제를 백엔드, Jetson, STM32 상태 전체에서 확인해야 한다.
3. ACK가 실제 출력 적용 결과를 나타내도록 STM32 피드백까지 연결해야 한다.
4. 작업 구역 이탈, GPS 이상, 센서 오류, MQTT 단절 시험을 수행해야 한다.
5. 저속·무부하 시험부터 시작하고 사람과 동물이 없는 통제 환경을 사용해야 한다.
6. 실제 계정과 인증서는 Git이 아닌 secret 관리 체계에 저장해야 한다.

## 테스트 공백

백엔드, 프론트엔드 단위 테스트와 Jetson 명령 변환 테스트는 존재한다. 실제 ROS 2 장비, STM32, 모터, 브로커 장애, 네트워크 지연, 다중 백엔드 인스턴스는 아직 검증되지 않았다.
